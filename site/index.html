What it does

Everything the desk does, in the order it does it.

Khulla follows a working day rather than an alphabet: what's out and overdue first, then the desk and the catalogue, then the people. The weekly jobs sit below the daily ones.

Every feature listed here is in the current release. Try them in the demo.

09:00 Opening up

Dashboard

What's out, what's overdue, which holds are waiting on the shelf and which copies were reported lost, before the first member walks in.

09:15 At the desk

Check out, return, renew

Scan a copy, pick a member, done. A return closes the loan and raises any overdue fine itself, so nobody works it out on paper. Loans can renew on their own when nobody is waiting.

Holds

Members waiting for a copy, in the order they asked. A returned copy waits on the hold shelf for as many days as you set, then goes to the next person.

Fines

What members owe, what's been collected and what was written off. Charge for a lost or damaged copy or a membership fee. Amounts are stored as whole paisa, so totals never drift.

Members

One register of borrowers with categories and membership renewal. Switch on one rule and the desk won't lend to anyone who is already late.

14:00 Behind the desk

Catalogue

Titles and their physical copies, kept separate the way a library thinks about them. Copies get barcodes numbered for you, and search finds a title from any three letters of it.

Labels

Scan barcodes one at a time or paste a whole accession list, then print spine labels and barcode stickers by the sheet.

Month end For the committee

Reports

Circulation over time, the collection by format, membership growth, fines raised against collected, and the most borrowed titles. Export to CSV.

Staff and roles

An account for everyone who works the desk, with four roles from Administrator down to Read only.

Backup and restore

Export the whole library as one file and restore it on any machine. Do it before an upgrade, before moving computers, before the end of term.

Why there's no server

A small library's catalogue isn't big data. It's a few thousand rows that have to be there at 9am, whether or not the internet is.

So Khulla runs from a database on your own machine. No hosting bill, no outage, nothing to migrate when a grant runs out, and no third party holding a record of who borrowed what.

What you don't need

  • A serverNothing to host, patch or pay for every month.
  • An internet connectionThe desk keeps working during an outage, because nothing it does goes online.
  • An account with anyoneStaff sign in to your installation, not to a service that can close.
  • To trust us with your recordsBorrowing history stays in the building. We never see it.

What to know the trade-offs

  • One machine is one libraryTwo desks can't share one catalogue yet. If your library needs that, tell us. It's the next big piece of work.
  • The web version lives in one browserClearing site data erases it. Use it as a second terminal, not the only copy.
  • Backups are yours to takeSettings → Backup exports one file. Make it a Friday habit.
Uninstalling keeps the catalogue

The database lives outside the app, so removing Khulla doesn't remove your records.

A newer file is never overwritten

An older build refuses to open a database a newer one wrote. It stops and says so instead of guessing.

Upgrades are tested, step by step

Every schema change is checked against a clean install, so an upgraded catalogue ends up the same as a new one.

Make it yours

It should look like your library, not like ours.

Name, logo, colour, currency and loan rules are all settings, with no code involved. For anything the settings don't cover, the whole source is yours to change, and we're happy to help.

macOS and iOS build from the same source but aren't published yet. Both need an Apple Developer account to produce something you can open.

Terminal 
$ git clone https://github.com/khulla-digital-library/khulla-digital-library.git
$ cd khulla-digital-library

$ dart pub global activate fvm   # once, if you don't have FVM
$ fvm install                    # the Flutter SDK pinned in .fvmrc
$ make bootstrap                 # resolve deps, link local packages
$ make build                     # code generation — required on a fresh clone
$ make localize

$ make run-windows               # or: make run-web, make run-linux
You'll need FVM, plus Visual Studio with Desktop development with C++ on Windows, or clang cmake ninja-build libgtk-3-dev on Linux.

For developers

Built in the open, and written to be read.

One Flutter codebase with a strict, written-down architecture. The design system is precise enough that this page borrows its tokens line for line.

  • Migrations are append-only.A shipped migration is never edited, because someone's catalogue was built by running exactly that SQL. Mistakes are fixed in the next one.
  • Money is never a float.Every amount is an integer of minor units behind a zero-cost type, so a year of daily fines can't drift by a rupee.
  • One file may hold a colour.Every hex value lives in app_palette.dart. Everything else reads tokens, which keeps eighty screens looking like one product.
  • Every screen has four states.Loading, error, empty and content, each designed on purpose. No flash of "nothing here" before the query has even run.

Questions

Before you install it.

Didn't find your question? Ask us and we'll add the answer here.

Is it really free?

Yes. Khulla is MIT licensed, with no paid tier, no hosted plan and nothing to renew. You can use it, change it and give it to other libraries.

Does it need the internet?

No. The catalogue is a SQLite database on the machine, and nothing the desk does goes online. You only need a connection to download Khulla or an update.

Where are our records kept?

On Windows, Linux and Android, in the app's data folder on that device, outside the app itself, so uninstalling doesn't delete them.

In the web version, they're in that browser's storage, and clearing site data erases them. Nothing is ever sent to us.

Can two computers share one catalogue?

Not yet. Each installation is its own library. The code already has a clear place for sync to go, and a library that genuinely needs several desks writing to one catalogue is what will make us build it. If that's you, tell us.

How do we move to a new computer?

Go to Settings → Backup on the old machine and export the library as one file. Install Khulla on the new one and restore from that file.

Is it safe to update?

A new version upgrades the database through tested migrations. If you ever open a database with an older version, Khulla refuses to open it rather than risk damaging it. Take a backup before upgrading anyway.

Can it work in Nepali, or in our currency?

The currency is a setting: the symbol, which side it goes on, and the digit grouping. The interface is in English today, but every string lives in one translation file, so adding a language is a well-defined job. We'd love help with it.

What about Mac and iPhone?

Both build from the same source, but we don't publish them yet, because a Mac or iOS build people can actually open needs an Apple Developer account. Until then, the web version works in Safari.
